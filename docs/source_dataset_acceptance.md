เอกสารนี้รวบรวมคำยืนยันของผู้ใช้ ข้อความหน้า Kaggle ภาพ S3 และผล CloudShell ที่ผู้ใช้ส่งมา พร้อมผลตรวจขนาดไฟล์ในเครื่อง ไม่ใช่การตรวจบัญชี AWS สดโดยผู้จัดทำเอกสาร การยืนยันใช้ข้อมูลคงที่ไม่ถือเป็นการอนุมัติ known issues หรือการรับมอบโดยทุกทีม

คำว่า “Updated 3 years ago” เป็นข้อความเวลาอัปเดตโดยประมาณของหน้า dataset ไม่ใช้อนุมานวัน export หรือเวลา snapshot วันที่ดาวน์โหลด เวลาอัปโหลด S3 และเวลารัน pipeline ก็ไม่ใช้แทนเวลา snapshot เช่นกัน

### 2.2 คำสั่งอ่านข้อมูลสำหรับตรวจซ้ำ

คำสั่งที่ผู้ใช้รันและส่งผลมาแล้ว:

```bash
aws s3api list-objects-v2 \
  --bucket thelook-dwh-20241022 \
  --prefix thelook/raw/initial-extract/ \
  --query 'Contents[].{File:Key,Bytes:Size,Uploaded:LastModified}' \
  --output table \
  --region us-east-1
```

หากต้องการตรวจ Versioning ซ้ำ ใช้คำสั่งอ่านข้อมูลด้านล่างได้ ผลคำสั่งนี้ยังไม่ได้รับจากผู้ใช้; สถานะ Disabled ข้างต้นมาจากการตรวจ Console ที่ผู้ใช้รายงาน ไม่จำเป็นต้องเปิด Versioning เพิ่มเพื่อทำตามเอกสารนี้

```bash
aws s3api get-bucket-versioning \
  --bucket thelook-dwh-20241022 \
  --region us-east-1
```

## 3. Known issues และกฎที่ระบบใช้อยู่

อ้างอิงรายละเอียดใน [Data dictionary และกฎ cleaning](dataset_dictionary_and_cleaning.md) หัวข้อ 10 และ [BI handoff](bi_handoff.md) จำนวนด้านล่างผูกกับชุดข้อมูลที่ตรวจแล้ว ไม่ใช่เกณฑ์ถาวรสำหรับชุดข้อมูลใหม่

| Issue | จำนวนที่พบ / ตัวหาร | แนวทางที่ระบบใช้อยู่ |
|---|---|---|
| CITY-01-users | 958 / 100000 users | เก็บ `city` เดิม; แปลงเฉพาะข้อความที่ trim และ casefold แล้วเท่ากับ `null` เป็น NULL ใน `city_clean`; ติด `city_missing_token` |
| CITY-01-events | 23080 / 2431963 events | ใช้กฎเดียวกับ users โดยไม่เติมเมืองจากผู้ใช้ พิกัด หรือรหัสไปรษณีย์ |
| DATE-01-items | 35872 / 118281 items ที่เทียบวันได้ | เก็บ `created_at` และ `shipped_at` เดิม; ติด `item_shipped_before_created` และ `item_dates_comparable`; ไม่ลบแถวหรือสลับวัน |

### 3.1 ข้อกำหนดสำหรับรายงานและ Dashboard

- หากแสดงเมือง ให้ใช้ `city_clean` และแสดง NULL เป็น **Unknown** หรือแยกกลุ่มค่าว่าง ไม่แสดงข้อความ `null` เป็นชื่อเมือง และไม่อนุมานชื่อเมืองทดแทน
- กฎ CITY-01 ไม่ครอบคลุมการแปลง `NA`, `N/A`, `None` หรือ `NaN` เป็น NULL โดยอัตโนมัติ
- ไม่ใช้ `order_items.created_at` คำนวณระยะเวลาจัดส่งจนกว่าสาเหตุจะได้รับการยืนยัน หากต้องใช้วันที่ระดับ order ต้องตรวจคู่วันที่และระบุนิยาม metric ให้ชัดก่อน
- สัดส่วน DATE-01 ใช้ตัวหาร 118281 แถวที่มีคู่วันเปรียบเทียบได้ ไม่ใช้จำนวน items ทั้งหมด 181759 แถว
- เก็บหมายเหตุว่าเวลา snapshot ต้นทางไม่ทราบ และข้อมูลเป็นชุดคงที่ Version 1; เวลาโหลด/เผยแพร่ไม่ได้รับรองความสดใหม่ของข้อมูลต้นทาง

## 4. ขั้นตอนส่งต่อและผู้รับผิดชอบ

ดำเนินการตามลำดับ โดยบันทึกหลักฐานก่อนเปลี่ยนสถานะเป็นเสร็จ:

| ลำดับ | งาน | ผู้รับผิดชอบ | เกณฑ์ปิด | สถานะ |
|---|---|---|---|---|
| 1 | ทบทวนและยืนยันข้อความรับทราบในหัวข้อ 3.2 | DW + BI | มีชื่อ วันที่ และหลักฐานการยืนยันของแต่ละทีม | รอยืนยัน |
| 2 | ทบทวนสิทธิ์อ่านข้อมูลและเส้นทางเชื่อมต่อฐาน `thelook_glue_validation` / schema `reporting` | Infra + BI โดย DW ให้รายละเอียดข้อมูล | เชื่อมด้วยสิทธิ์ read-only ที่ตกลงและทดสอบการเข้าถึงตามบทบาท; ไม่ส่ง admin password | รอดำเนินการ/หลักฐาน |
| 3 | เชื่อม reporting views และตรวจยอดกับตัวกรอง Dashboard | BI + DW | ยอดและ grain ตรงกับ BI handoff; ตรวจ distinct orders จาก detail ไม่บวกยอด distinct ข้ามกลุ่ม; ตกลงการแสดง Unknown/status/UTC/ข้อจำกัด snapshot | รอดำเนินการ/หลักฐาน |
| 4 | ส่งเอกสารและรับมอบงานจริง | DW ส่งให้ Infra + BI | บันทึกผู้ส่ง ผู้รับ วันที่ และรายการที่ยอมรับหรือยังค้าง | รอรับมอบ |

## 5. เอกสารอ้างอิงและวิธีใช้ร่วมกับ checklist เดิม

- [Checklist และเจ้าของงาน](handoff1.md): ใช้คู่กับเอกสารนี้ โดยส่วน new-snapshot orchestration/schedule อยู่นอกขอบเขตข้อมูลคงที่ตามข้อตกลงครั้งนี้ ไม่ใช่งานที่ deploy เสร็จแล้ว
- [Data dictionary และกฎ cleaning](dataset_dictionary_and_cleaning.md): รายละเอียด CITY-01, DATE-01 และข้อจำกัด provisional-v1
- [DW handoff](dw_handoff.md): batch ที่ผ่าน ผลทดสอบ ทรัพยากรและข้อจำกัดที่มีหลักฐาน
- [BI handoff](bi_handoff.md): views, grain, นิยาม metric และเกณฑ์ตรวจ Dashboard
- [Reporting acceptance](report/reporting_acceptance_20261024.md): ตัวเลขและผลตรวจ reporting ที่ผู้ใช้ส่งหลักฐานแล้ว

เอกสารนี้เพิ่มข้อสรุปเรื่องข้อมูลคงที่และหลักฐาน S3 โดยคงเอกสารเดิมไว้ รายการเวลา snapshot/ความครบถ้วนจาก BigQuery ยังคงเป็นข้อจำกัดที่ไม่ทราบ ส่วนการยอมรับ known issues การเชื่อม BI และการรับมอบต้องเก็บหลักฐานเพิ่มเติมตามตาราง ไม่ถือว่าเสร็จจากการจัดทำไฟล์นี้เพียงอย่างเดียว
